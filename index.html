How this works

This follows the game's own rule (in-game manual, "Component Delay"): the game runs at 60 ticks per second and every component takes one tick to pass a signal on — a lever through 10 Data Routers reaches a Datameter after 11 ticks. Each tick, every block computes from what all blocks output on the previous tick, so any feedback loop is legal, just as in the game.

Blocks marked STATE also remember values across ticks. Use an Initializer on outputs that drive thrusters or decouplers — circuits output junk for a few ticks while their paths fill up.

Drag an output dot onto an input dot to wire them. An output already in use will refuse a second wire — clone it with a Data Router first, same as the real part.

Click a node or wire to select it, then press Delete/Backspace to remove it. Shift- or Ctrl-click adds blocks to the selection, Shift-drag on empty canvas box-selects, and Ctrl+A selects everything; drag any selected block to move the group.

Ctrl+C / Ctrl+X / Ctrl+V copy, cut and paste the selected blocks. Wires between blocks in the group are kept; wires leading out of it are not. Pastes land where you last clicked on the canvas.

Power

Red square ports are power ports; drag between two of them to lay a power cable. Each tick, cables, Power Routers, closed Fuse Boxes and unblocked Power Blockers join ports into one circuit. A circuit is powered while its generators cover demand or its batteries still hold charge; unpowered sensors read 0 and actuators stop. The game files leave every P/s figure and battery capacity out, so set power_ps, gen_ps and capacity from each part's in-game tooltip.

Part list

Every part here exists in the game (checked against its Localization.csv). There is no NOR gate in the game — build it as OR → NOT. Condition: unwired True reads 1, unwired False reads 0. Differentiator: current value minus the value interval ticks earlier. Hover a part or port to read the game's own text for it. Sensors and controls take their reading as a setting. The BPS and ETA indicator formulas are not in the game files and are approximated from stopping distance. Not modelled: fuel, heat, physics, and Frame Quarter With Ports chains (one tick for the whole chain).

Generate an in-game blueprint

Logic parts become real parts, packed into as few 4×4×4 frame quarters as possible and joined face to face where they can be. Every other part (sliders, toggles, sensors, thrusters…) becomes a labelled cable stub on the blueprint's edge. Where it fits, the stubs come out side by side as one row of parallel cables; otherwise inputs leave through one face and outputs through the opposite face, each group in a row. Logic parts and internal cables are black; input cables and labels green, outputs red. Several tries run in parallel and the smallest layout wins.
